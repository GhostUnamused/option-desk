# Optionwise — notes for Claude Code

Local NSE index-options workstation (also packaged as a self-updating Windows app): guided lessons, live quotes and charts, broker-style option chain, strategy builder, paper trading with a dummy balance. Owner is a beginner learning options; keep UI copy plain and explain finance terms in the interface.

## Run
- `node server.js` → http://localhost:4321 (live NSE). `node server.js --sim` (or `--replay`, `MOCK=1`) → replay mode: real past NSE days from a local SQLite store, separate account file. The UI still calls it the simulated/replay switch.
- Windows: `start.bat`, `start-simulated.bat`. Node ≥ 22.13 (replay uses the built-in `node:sqlite`; live mode still runs on older Node), zero npm dependencies — keep it that way unless there's a strong reason.
- Tests: `npm test` (`node --test "test/*.test.js"`, built-in runner). `test/snapshot.test.js` guards the replay as-of gate; keep it passing.
- Desktop app: `node tools/build.mjs` → `dist/Optionwise.exe` (Node single executable, GUI subsystem, opens an Edge/Chrome app window). Release: raise `version` in package.json, then `node tools/release.mjs "notes"` (needs `gh` and `updates.github` in package.json). Bump `LAUNCHER_VERSION` in `tools/launcher.cjs` only when that file changes; installed apps then download a new exe too.
- Signing (optional, `tools/build.mjs`): `SIGN_CERT_THUMBPRINT` (cert store) or `SIGN_PFX` + `SIGN_PFX_PASSWORD` runs `signtool sign /fd SHA256 /tr <SIGN_TIMESTAMP_URL, default http://timestamp.digicert.com> /td SHA256` then `signtool verify /pa` on dist/Optionwise.exe; any failure stops the build (errors never echo the command line, which can hold the password). signtool is `SIGNTOOL`, else the newest Windows Kits 10 one, else PATH. Unset: unsigned build plus one "unsigned" line. Signing happens after `rebrand` and before hashing, so `version.json`'s `exeSha256` (what the updater checks) is of the signed file; `version.json` also says `signed`. `release.mjs` appends a "Checksums (SHA-256)" block (exe, app-bundle.json, version.json, as uploaded) and a `Get-FileHash` line to the notes. Certificates (`*.pfx`, `*.p12`, …) are git-ignored; never commit one or its password.
- Testing the exe: always isolate it from the owner's install with `OPTIONWISE_HOME=<scratch dir> OPTIONWISE_NO_WINDOW=1 PORT=4399` (and `OPTIONWISE_UPDATE_URL=http://127.0.0.1:<port>/` for a fake release). Commands run by Claude Code here are inside the Claude desktop app's MSIX container, so their %LOCALAPPDATA% writes land in %LOCALAPPDATA%\Packages\Claude_*\LocalCache\Local: the owner's real Optionwise folder and log are not what you see. Never run test servers on 4321, the app's port; the preview config uses 4322 (`--port`).
- Test UI changes in `--sim` mode first. Replay needs some history in `replay.db`: download a few months from the Replay tab (NSE's archive host `nsearchives.nseindia.com` is reachable from here; the live JSON API may not be).

## Layout
- `server.js` — http server, JSON API (`/api/indices`, `/api/expiries`, `/api/chain`, `/api/intraday`, `/api/daily`, `/api/option-intraday`, `/api/option-history` (ATM IV + PCR per day), `/api/news`, `/api/events`, `/api/account`, `/api/preview`, `/api/order`, `/api/exit`, `/api/reset`, `/api/broker` (provider status; POST connects), `/api/broker/select`, `/api/broker/forget`, `/api/recorder` (live minute recording status; POST `{enabled}`), `/api/stream` (INDstocks server-sent ticks), `/api/option-candles`, `/api/expired/{expiries,contracts,candles}`, `/api/stocks`, `/api/watchlist`, replay-only `/api/replay` (status), `/api/replay/{download,download/cancel,minutes/download,minutes/cancel,start,step,end,settings,journal}`, plus `/api/meta` and the desktop endpoints `/api/update`, `/api/restart`, `/api/ping`, `/api/bye`, `/api/quit`) and static files from `public/`.
- `lib/nse.js` — NSE provider (cookie warm-up on `/` and `/option-chain`, 4 s cache, de-duped requests, ~120 ms spacing). `lib/replay/provider.js` — same interface, answered from history (see Replay below). A broker provider should implement the same methods: `indices, marketStatus, expiries, chain, intraday, optionIntraday, daily`.
- `lib/indstocks.js` — `IndstocksProvider`: INDstocks (INDmoney) official API for live indices, expiries, option chain (`/market/option-chain`, chain ids are `NFO_<security_id>`), 1-minute and daily candles; every method falls back to the wrapped `NseProvider` (no token, outage), and a 401/403 parks INDstocks (`TokenError`) until a new token is set. Raw token in `Authorization` (no Bearer), 5 calls/s, tokens last 24 h. Market status always comes from NSE (or the clock). Index ids come from `/market/instruments?source=index`; index quotes and candles use `NIDX_<id>` (undocumented; `indexCode` probes it once). OI and volume arrive in units (divided by the lot); OI change is `open_interest_change` (percent) from `/market/quotes/full`, and one never-traded contract makes a whole quote batch fail, so `quotes()` splits refused batches. Candle `ts` is true epoch seconds. Tested in `test/indstocks.test.js` with a fake API.
- `lib/fyers.js` — `FyersProvider`: FYERS API v3 read-only market data for NSE/BSE index option chains, quotes, intraday/daily index charts, live-option charts, expiry listings, and expired contracts/charts. User enters Client ID plus access token; the token expires daily at 06:30 IST. Requests use `app_id:access_token`; credentials are saved through `SecretFile` separately from INDstocks. Standard-plan history limits apply, including 10 expired intraday-history requests per day. FYERS currently does not provide the app's stock-options picker. If it fails, supported index data falls back to `NseProvider`.
- `lib/upstox.js` — `UpstoxProvider`: Upstox read-only index quotes/chains, expiry lists, index history, and active option charts. Users paste one manually generated access token, which expires at 03:30 IST. Stock options are not yet enabled. Expired-option history needs Upstox Plus and is not called. Supported index data falls back to `NseProvider`.
- `lib/kotak.js` — `KotakProvider`: Kotak Neo consumer-key-only read-only quotes, option expiries/chains, and active-contract candles for NSE/BSE indices; index charts use NSE. No stocks, expired contracts, or stream. User pastes one consumer key, saved as `broker-kotak.dat`; no login, TOTP, or MPIN is used. Historical candles use Kotak's 1/5/60-minute and daily intervals within its documented request windows. If the provider fails, index option data falls back to `NseProvider`.
- `lib/breeze.js` — `BreezeProvider`: read-only ICICI Direct Breeze NSE index option chains and active-contract candles. The NSE public endpoints still supply indices, expiry dates and index charts. Breeze requires App Key, Secret Key and a manually generated daily API_Session; only the derived session token and app credentials are saved in `broker-breeze.dat`. Its API requests are signed with the documented SHA-256 checksum; the adapter does not call order APIs.
- `lib/angelone.js` — `AngelOneProvider`: read-only Angel One SmartAPI NSE index data, option chains/Greeks and active-contract/index candles. The public scrip master is cached for 24 hours; chains quote up to 100 contracts nearest the spot in batches of 50 to respect SmartAPI's market-data limit. User enters API key, client code, PIN and a daily TOTP; session credentials are saved in `broker-angelone.dat`. No order API is used.
- `lib/bars.js` — candle helpers for the broker adapters: chart `t` is IST wall-clock seconds for intraday bars and midnight UTC for daily bars (`wallClock`, `fromEpoch`, `tidy` sorts/dedupes, `lastSession`). Adapters and `BrokerManager` are tested with fake APIs in `test/brokers.test.js`; the endpoints of FYERS/Upstox/Kotak/Breeze/Angel One have not been checked against real accounts.
- `lib/brokers.js` — `BrokerManager` selects one data provider at a time and delegates the shared interface. The per-install selection is `broker-settings.json`; credentials stay in provider-specific secret files. Replay's minute downloader builds its own providers in `--sim` (INDstocks, Upstox) from the saved credentials, preferring the broker chosen in `broker-settings.json`.
- `lib/stream.js` — `PriceStream`: INDstocks price WebSocket (`wss://ws-prices.indstocks.com/api/v1/ws/prices`, token in the `Authorization` header, frames are JSON-encoded strings, `instrument` is the bare id). Indices subscribe in `indices()`, the contracts of each chain the page asks for in `chain()` (dropped 3 min after the last ask). Ticks freshen REST answers (`provider.live(id)`) and go to the page as server-sent events on `/api/stream`, keyed by the page's names (`NIFTY`, `NFO_47161`). Its timers catch everything: a stream fault must never crash the server.
- Underlyings: `INDICES` also holds SENSEX/BANKEX (`exchange: 'BSE'`, `broker: true`: INDstocks and supported provider adapters) and, at runtime, followed stocks (`addStock`, `kind: 'stock'`, saved in `watchlist.json`; the list of ~200 F&O stocks is built daily from the fno + equity instrument files into `fno-stocks.json`). `IndstocksProvider.underlying(symbol)` maps a symbol to their codes: `NIDX_`/`BIDX_`/`NSE_` for quotes and candles, `NFO_`/`BFO_` for contracts. BSE chains have empty `security_id`s, filled from `/market/instruments/search` (`contractIds`). Chains carry `lot` (and each side its contract's lot). Charges use `CHARGES.exchangeBse` for BSE; stocks get a wider margin scan (`PAPER.marginScanPctStock`) and settle in cash at intrinsic (real stock options settle by delivery).
- Option history (INDstocks): `optionCandles(id, range)` (1D/5D/1M/life) for the drawer's candle chart (`public/js/candles.js`), expired contracts (from about April 2025) via `expiredExpiries/Contracts/Candles` for the Expired options panel (`public/js/expired.js`, Option chain tab).
- `lib/secrets.js` — broker credential storage: INDstocks source runs may still use `.env` (`INDSTOCKS_TOKEN`, git-ignored and never in the exe bundle, see `.env.example`). Credentials pasted in `public/js/broker.js` go to `POST /api/broker` and are checked by the provider before being saved through `SecretFile`: DPAPI-encrypted for the current Windows user, user-readable only elsewhere. INDstocks uses `broker.dat`; other providers use separate `broker-<provider>.dat` files. Credentials never return to the page or log; POSTs with a foreign `Origin` are refused.
- `lib/desktop.js` — data folder (`%LOCALAPPDATA%\Optionwise\data`, shared by source runs and the exe; migrates an old project `data/*.json` once), update check/install from GitHub Releases, restart (live/sim switch), quit when the last window closes. `tools/launcher.cjs` is the exe entry: unpacks the embedded app to `%LOCALAPPDATA%\Optionwise\app\<version>` and loads its server.js (via require(esm), so no top-level await in server/lib). Exe logs: `%LOCALAPPDATA%\Optionwise\logs`.
- `lib/paper.js` — paper engine: buys at ask / sells at bid, per-leg charges, netting, realized P&L, margin estimate (`marginFor`), expiry settlement at intrinsic, equity snapshots. State in `paper.json` under the data folder (atomic writes; `file: null` keeps it in memory). The clock is injectable (`opts.now`) and fills carry the contract's lot (`q.lot`), which is how the replay account reuses it.
- `lib/news.js` — headlines from RSS, no keys: live = Google News search + Economic Times / Business Standard / Mint market feeds (3 min cache); replay = Google News `after:/before:` search for the days before the replay date, kept only if published by that day's 15:30 close (date-only items, stamped 08:00 GMT, wait for the next day), cached in `news-cache.json`. `lib/sentiment.js` scores headlines with a small finance word list (`word*` = stem, else exact word) and tags shocks (severity 2 = can gap the market, 1 = watch). `lib/events.js` — curated market-moving days (budgets, elections, wars, policy shocks) for chart markers; keep dates accurate. Blind replay returns no news or events (headlines give the date away).
- `lib/opthist.js` — live ATM IV / PCR history: `replay.db` through `getSnapshot(store, today).optionHistory` if it exists, plus a log the app keeps (`option-history.json`: a point per session, dated from the chain's timestamp, and today's per-minute samples). Same definitions as replay: IV of the nearest expiry ≥ 7 days out, PCR of the nearest expiry.
- `lib/config.js` — indices, lot sizes (Jan 2026 revision), `CHARGES` (₹20/order discount-broker brokerage + dated STT/NSE/SEBI/stamp/GST rates, looked up with `rateOn(list, date)` so replay pays the rates of its day; `legCharges`/`settlementCharges` in paper.js itemise them), margin model, risk-free rate; replay tables `LOT_HISTORY`/`KNOWN_LOTS` (lot by trade date), `EXPIRY_RULES` (weekly/monthly weekday by date), `REPLAY` (symbols, slippage model, defaults), helpers `lotOn`, `expiryRule`, `expiryKind`.
- `public/js/` — plain ES modules, no build step. `app.js` (header, India VIX block, tabs, beginner guide, tab intros, polling every 5 s), `indicators.js` (indicator maths + the `STUDIES` catalogue, groups, presets; no DOM, tested in `test/indicators.test.js`), `studies.js` (`StudyChart`: price chart plus one synced chart per oscillator pane, since Lightweight Charts 4 has no panes; each pane holds an invisible anchor series with every bar time so logical ranges line up; crosshair/zoom follow the chart under the mouse; TradingView-style legend: one short line per study (`short(p)`), eye/gear/× on hover, fold arrow (`legendCollapsed`); band fills via the `BandFill` series primitive (`fills` in a study's output); markers on one bar merge; Indicators menu, choices (`on`, `params`, `hidden`) in localStorage `desk:studies`), `live.js` (applies streamed ticks), `stocks.js` (follow stock options when the selected adapter supports them), `broker.js` (provider selector and data pill), `newsfeed.js` (News & sentiment panel), `learn.js` (Learn tab: 6 guided lessons + Black–Scholes slider playground + Greeks cheat sheet; progress in localStorage), `glossary.js` (plain-English term tooltips via `term()`), `state.js` (shared state + event bus: quotes, symbol, expiries, chain, account, addLeg, goto; `account` fires only when the account changed, and timed refreshes in chain/strategy/markets skip redraws when nothing changed, so hover read-outs survive replay), `markets.js`, `chain.js`, `drawer.js` (option detail), `ticket.js` (order dialog, single or basket), `strategy.js`, `positions.js`, `payoff.js` (P&L math + SVG payoff chart), `bs.js` (Black–Scholes, shared with server; `setClock`/`now` is the page's "now", set to the replay day's close in replay), `util.js`, `replay.js` (Replay tab + control bar under the tabs; only in replay mode).
- `public/vendor/` — TradingView Lightweight Charts 4.2.0 (UMD global `LightweightCharts`), served locally.

## NSE endpoint notes (unofficial, may change)
- `/api/allIndices`, `/api/marketStatus`, `/api/option-chain-contract-info?symbol=`, `/api/option-chain-v3?type=Indices&symbol=&expiry=DD-Mon-YYYY`
- Intraday index: `/api/NextApi/apiClient/indexTrackerApi?functionName=getIndexChart&&index=NIFTY%2050&flag=1D` — timestamps are IST wall-clock encoded as UTC epoch ms; points flagged `PO` are pre-open.
- Option intraday: `/api/chart-databyindex?index=<identifier>` (e.g. `OPTIDXNIFTY19-10-2026CE22500.00`).
- Daily history: `/api/historicalOR/indicesHistory?indexType=NIFTY%2050&from=DD-MM-YYYY&to=DD-MM-YYYY`, VIX: `/api/historicalOR/vixhistory?from=&to=` — fetched in 90-day windows.

## Replay (the simulated mode)
- Data: per trading day, the F&O bhavcopy (`nsearchives.nseindia.com/content/historical/DERIVATIVES/YYYY/MON/foDDMONYYYYbhav.csv.zip` until 2024-07-05, then UDiFF `content/fo/BhavCopy_NSE_FO_0_0_0_YYYYMMDD_F_0000.csv.zip`) and `content/indices/ind_close_all_DDMMYYYY.csv` (NIFTY 50, NIFTY BANK, India VIX OHLC). No cookies needed. Weekends are probed too (budget days, muhurat). Only NIFTY/BANKNIFTY index options are kept (`REPLAY.symbols`). Volume is contracts in both formats; OI is units.
- `lib/replay/bhavcopy.js` — URLs, zip reader (central directory; local headers lack sizes), `parseFo` (detects format by header), `parseIndexClose`, `inferLot` (old format has no lot: gcd of a contract's OI figures, checked against `LOT_HISTORY`/`KNOWN_LOTS`; lots are per contract during revisions).
- `lib/replay/store.js` — `replay.db` (node:sqlite via `process.getBuiltinModule`; live mode opens it only for the minute recorder, and `busy_timeout` lets both processes write): `days` (trading/holiday/error), `options`, `indices`, `settings`. Writes and calendar questions only.
- `lib/replay/snapshot.js` — **the as-of gate** (`optionHistory` gives ATM IV and PCR per day up to as-of). All replay market reads go through `getSnapshot(store, asOf, { at })`; every query must bind `date <= ?`/`= ?`/`< ?` (daily rows) or `ts <= ?` (minute rows), and each returned row is checked (`AsOfViolation`): daily rows by `date`, minute rows by `ts` (a bar is visible once `ts + 60 <= at`). With `at` before 15:30 the snapshot is `live`: today's daily rows (bhavcopy, index close) are refused, today's OHLC comes from minute bars (`todayBar`, `indexMinutes`), the chain from `minuteChain` (last trade before the minute, day volume so far, previous day's OI, lot from the bhavcopy), `optionHistory` stops at the previous day. At 15:30 it is the plain daily snapshot. Price = close if it traded, else NSE's settlement price. IV is backed out of that price per row (`impliedVol`, configurable risk-free rate) with Greeks; `T` runs to 15:30 IST on expiry from 15:30 on as-of.
- `lib/replay/fills.js` — bid/ask around the day's price: half-spread grows with distance from spot and with low volume (`REPLAY.slippage`), on the 0.05 tick. `lib/replay/account.js` — `ReplayAccount extends PaperAccount`: replay clock, `replay.json`, zero-volume strikes refused (`checkQuote`), marks at the day's price, one equity point per day, `journal()` (trades with notes, P&L by day, summary stats).
- `lib/replay/engine.js` — session (`start`, `step` by minutes/close/day/week/expiry, walking every trading day in between so settlements and equity points happen, `end`), `serial()` lock for steps and orders, `blindDays()`. Minute-by-minute sessions (`intraday: true`) keep `session.minute` (minutes after midnight IST, null = at the close; a number, not a timestamp, so blind mode has nothing to shift): a day opens at 09:16 (`REPLAY.intraday.firstMinute`) when `store.minuteReady(day)`, else shows at its close; leaving a running day first takes it to its close. One equity point per day (the latest replaces earlier ones). `lib/replay/download.js` — background downloader (3 workers, retries, progress). `lib/replay/minutes.js` — `MinuteDownloader`: 1-minute history from any provider with a minute-history source (`provider.minuteHistory()`, interface documented in the file; INDstocks' is `indstocksHistory(raw)`: index minutes from 2024-03-19, expired contracts from the 2025-04-03 expiry, 50 symbols a call; Upstox needs its Plus plan (`UDAPI1149` otherwise), has the last six months of expiries, one contract a call paced at 1/s): index bars for NIFTY, BANKNIFTY, INDIAVIX in 7-day windows, then per expired expiry the strikes `strikesEachSide` steps beyond the index range over `daysBefore` days; also starts the bhavcopy download for the same dates. `lib/replay/recorder.js` — `MinuteRecorder` (live mode, any data source incl. NSE website, on by default, setting `recordMinutes` in replay.db): during market hours samples index levels every 5 s into OHLC minute bars and, once a minute at :45, the chains of expiries within `daysBefore`, saving a bar per contract that traded (volume = change in day volume, in units). Recorded days need the bhavcopy before `minuteReady`; `ReplayEngine.fillRecordedDays()` fetches it (at most every 30 min). Recording stops when the app quits (last window closed). Tables `minute_index`, `minute_contracts` (id per option), `minute_options` (close in paise, volume in units), `minute_days` (bar counts per date and symbol), `minute_expiries` (what was fetched). `lib/replay/blind.js` — blind mode: `server.js` shifts every date in responses by a multiple of 7 days (and back on requests), so the page needs no blind logic. Keep any new date fields as ISO strings, or epoch numbers under `t`/`openedAt`/`now`, or they will leak in blind mode.
- Backtester (not built yet): loop `store.tradingDaysBetween(from, to)`, take `getSnapshot(store, day)` for each, let a rule decide orders from that snapshot alone, and run them through a `ReplayAccount` with `file: null` and a clock pointing at the day (`ReplayEngine(dir, { accountFile: null })` already works headless; see `test/replay.test.js`). `EXPIRY_RULES`/`lotOn` answer "next weekly" and lot questions for rules.

## Conventions
- Indian number formatting (`en-IN`, lakh/crore via `util.compact`), ₹ amounts, IST times.
- Colors only via CSS tokens in `public/css/app.css` (single premium-black theme, TradingView-style). Gains `--up`, losses `--down`; No blue: `--accent` is a white/silver fill (black text on it), `--accent-text` for highlighted text. India VIX has its own header block (`renderVix` in app.js, bands in `util.vixMood`).
- Paper trading only; never add real order placement.
- FYERS/Upstox/Kotak/Breeze/Angel One are flagged `experimental` in `public/js/broker.js` until verified against a real account; remove the flag per provider once checked.
- NSE's Terms of Use (clauses 8, 9) restrict automated collection and virtual-trading use of its site content; README states this and recommends a broker source. Keep that notice. NSE website access is gated: `nseGate` in lib/nse.js is closed in live mode until the person opts in (`nse` in broker-settings.json, `POST /api/broker/nse`, `needsChoice` in broker status); every NseProvider request goes through it, so new NSE calls need no extra code. A first broker connection (`connect`) turns `nse` on as a backup unless the person already chose (`nseChosen`, set by `setNse`), so an expired token still has prices. Migration: a settings file without an `nse` key plus saved (not `.env`) broker credentials means a pre-0.10 install, so `nse` becomes true once and is written down; fresh installs start off until they connect or opt in.

## Known gaps / next ideas
- Market orders only (no limit/stop orders, no GTT).
- Margin is an estimate, not SPAN.
- Stock options are currently available only through INDstocks; BSE index options depend on selected provider; expired-contract history is provider-specific and not universal.
- Live IV history only reaches as far back as downloaded replay history plus the days the app has been running. Indicator line colours are `--s1..--s7` tokens (no blue).
- News sentiment is a word list, not a model; `lib/events.js` needs new entries added by hand. The index has no volume, so no volume indicators (OBV, VWAP).
- Replay is NIFTY/BANKNIFTY only, and blind mode can't hide the index level itself (NIFTY at 8,000 says "2016"). Downloaded minute history needs INDstocks (index minutes from 2024-03-19, VIX from 2024-05-21, option minutes from the 2025-04-03 expiry) or Upstox Plus (last six months), and only covers contracts that have expired (so not the last few days before today); recorded days cover only days the app was open, sampled once a minute (the close is the price near :45), strikes around the money only, no intraday OI (yesterday's is shown). INDstocks' expired-contract `lot_size` is wrong, so lots come from the bhavcopy. About 150 MB a month in replay.db (`daysBefore` is 35 days for both indices, so each day has the next four or five NIFTY weeklies). Expiries listed that day without minute prices come back from `/api/expiries` as `unpriced` and show disabled in the chain.
- INDstocks: market status and holidays still come from NSE; the 1D index chart still redraws every ~9 s rather than per tick. Minute replay is built (see Replay).
